================================================================
Q1.1  Insert a row in DEPARTMENT that references a row in EMPLOYEE.
      Then try to delete the referenced row. What happens?
================================================================

-- The referenced employee must exist first.
INSERT INTO EMPLOYEE (ssn, fname, lname, salary, dno)
VALUES ('666666666', 'Frank', 'Black', 40000.00, 1);

-- Insert a department whose manager is that employee.
INSERT INTO DEPARTMENT (dnumber, dname, mgr_ssn)
VALUES (4, 'Marketing', '666666666');

Output:
Query OK, 1 row affected
Query OK, 1 row affected

-- Now try to delete the referenced employee.
DELETE FROM EMPLOYEE WHERE ssn = '666666666';

Output (error):
ERROR 1451 (23000): Cannot delete or update a parent row:
a foreign key constraint fails (`company`.`department`,
CONSTRAINT `department_ibfk_1` FOREIGN KEY (`mgr_ssn`)
REFERENCES `employee` (`ssn`))

Explanation: Referential integrity is enforced. DEPARTMENT.mgr_ssn
points to the employee, so MySQL refuses to delete the parent row.
You must first set mgr_ssn to NULL or another employee, or delete
the department, before deleting the employee.

================================================================
Q1.2  Insert a row in EMPLOYEE that references a row in DEPARTMENT.
      Then try to delete the referenced department. What happens?
================================================================

INSERT INTO EMPLOYEE (ssn, fname, lname, salary, dno)
VALUES ('777777777', 'Grace', 'Hall', 39000.00, 4);

Output:
Query OK, 1 row affected

DELETE FROM DEPARTMENT WHERE dnumber = 4;

Output (error):
ERROR 1451 (23000): Cannot delete or update a parent row:
a foreign key constraint fails (`company`.`employee`,
CONSTRAINT `employee_ibfk_1` FOREIGN KEY (`dno`)
REFERENCES `department` (`dnumber`))

Explanation: EMPLOYEE.dno still references department 4.
MySQL rejects the delete (same rule as Q1.1, opposite direction).

================================================================
Q1.3  If mgr_ssn and Dno are both NOT NULL, how would you insert
      the first row in EMPLOYEE or DEPARTMENT?
================================================================

The problem: both columns are NOT NULL and each references the other
table, so neither table can get its first row (chicken-and-egg).

Solutions:

(a) Make one of the two FK columns nullable (the usual fix).
    EMPLOYEE.dno or DEPARTMENT.mgr_ssn must allow NULL, OR
    the FK must be added AFTER the row exists.

(b) Insert with a temporary valid value / disable checks:

    SET FOREIGN_KEY_CHECKS = 0;
    INSERT INTO DEPARTMENT (dnumber, dname, mgr_ssn)
    VALUES (1, 'Research', '111111111');   -- mgr not yet real
    INSERT INTO EMPLOYEE (ssn, fname, lname, salary, dno)
    VALUES ('111111111', 'Alice', 'Smith', 55000.00, 1);
    SET FOREIGN_KEY_CHECKS = 1;

    (Then verify with SELECT and fix any mismatches.)

(c) Create the table WITHOUT the FK, insert the first rows, then
    ALTER TABLE ... ADD FOREIGN KEY once both rows exist.

Recommended: (a) make mgr_ssn nullable, because a department can
legitimately have no manager yet. This is the cleanest design.
